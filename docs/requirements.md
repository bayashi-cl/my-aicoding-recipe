# 要件定義書

## 1. プロジェクト概要

### 1.1 目的
AIコーディングの理想的な開発環境を探るためのPoC。実際にWebアプリケーション（Notesアプリ）を題材に開発を進めながら、以下の2つの観点で「人間とAIが共存する開発環境」のあり方を検証する。

- **人間目線での開発体験**: 人間がAIの作業を把握・レビューし、適切に介入できる環境
- **クラウド上のAIへのハンドオフ**: ローカルAIとクラウド側AI（リモートエージェント、GitHub連携等）の役割分担

### 1.2 検証ゴール
- AIコーディングを日常的に運用する上で必要な「型」を、再利用可能な構成として整理する
- 構築した環境そのものが、将来の別プロジェクトでテンプレートとして活用できる状態を目指す
- 単なるアプリ完成ではなく、**開発プロセスと開発環境の質**を成果物とする

### 1.3 スコープ外（明示）
- 本番運用品質のセキュリティ・スケーラビリティ
- 認証・認可（PoCのため未実装）
- AWSへの実デプロイ（IaCの作成までで止める）
- 多人数同時編集・リアルタイム同期

## 2. PoC題材: Notesアプリ

### 2.1 概要
シンプルなメモ管理用のWebアプリケーション。CRUDを軸に、検索・タグ付け・Markdown表示を備える。

### 2.2 機能要件

| ID | 機能 | 内容 |
|----|------|------|
| F-01 | メモの作成 | タイトル、本文（Markdown）、タグを指定して保存できる |
| F-02 | メモの一覧表示 | 作成日時の新しい順に一覧表示。タグでフィルタ可能 |
| F-03 | メモの詳細表示 | 本文をMarkdownレンダリングして表示 |
| F-04 | メモの編集 | タイトル、本文、タグを更新できる |
| F-05 | メモの削除 | メモを削除できる（論理削除ではなく物理削除でよい） |
| F-06 | タグの管理 | メモにタグを複数付与可能。タグはメモ作成時に動的に生成される |
| F-07 | 全文検索 | タイトル・本文・タグを横断したキーワード検索 |

### 2.3 データモデル（概要）

- **Note**: id, title, body (Markdown), tags (string[]), createdAt, updatedAt
- **Tag**: タグはNoteに紐づく文字列配列として保持（独立テーブルにするかは設計フェーズで判断）

### 2.4 非機能要件

| 観点 | 要求水準 |
|------|----------|
| 性能 | PoCのため特に定めず、ローカルで体感できる程度の応答性があればよい |
| ブラウザ対応 | モダンブラウザの最新版のみ（Chrome/Firefox/Safari/Edge） |
| アクセシビリティ | 最低限のキーボード操作のみ |
| ログ | API側で標準出力に構造化ログを出せること（AIが状況把握しやすいように） |
| データ永続性 | ローカル開発時はDockerボリュームに永続化されること |

## 3. AI開発環境への要件

PoCの「もうひとつの成果物」として、以下のAI開発環境を構築する。

### 3.1 セッション間の引き継ぎ・並行作業

| ID | 要件 | 内容 |
|----|------|------|
| A-01 | Git worktreeによる並行開発 | 複数のClaudeセッションを別ブランチ・別worktreeで動かし、並行に作業させる仕組み |
| A-02 | PR/Issueによる引き継ぎ | 作業単位をGitHubのPR/Issueに対応させ、コメントスレッドを共有コンテキストにする |
| A-03 | 長期コンテキストの保持 | CLAUDE.mdおよびmemory機能で、プロジェクト固有の文脈をセッションをまたいで保持 |

### 3.2 レビューとフィードバックのフロー

| ID | 要件 | 内容 |
|----|------|------|
| A-04 | PRベースのレビュー | AIの成果物はPRとして提出され、人間（または別のAI）がレビューする |
| A-05 | 自動レビューの併用 | `/review`や`/ultrareview`、CIによる静的解析を経由した上で人間がレビュー |
| A-06 | フィードバックの記録 | レビューで指摘された内容のうち、再発を防ぎたいものをmemoryまたはCLAUDE.mdに蓄積 |

### 3.3 クラウド上のAIへのハンドオフ

| ID | 要件 | 内容 |
|----|------|------|
| A-07 | リモート実行 | ローカルで作業を組み立てた後、長時間タスクをClaudeのリモート/Cloud Agentに委譲できる |
| A-08 | GitHub連携の非同期作業 | Issue/PRをトリガに、GitHub Actions等でAIが自律的に動く構成も検証対象 |
| A-09 | 一貫したコンテキスト | ローカル↔リモート間で、同じCLAUDE.mdとプロンプト方針が共有される |

### 3.4 隔離された実行環境

| ID | 要件 | 内容 |
|----|------|------|
| A-10 | エージェントの隔離 | エージェントが任意のコマンドを実行しても、ホスト環境を汚染しないこと |
| A-11 | 再現性 | 別マシン・別開発者でも同じ環境を立ち上げられること |
| A-12 | アプリ実行環境との一致 | エージェントが触る環境と、アプリが動く環境（DB含む）の差異を最小化すること |

## 4. 制約事項

| 項目 | 内容 |
|------|------|
| 言語 | フロントはTypeScript（React）、APIはPython（FastAPI）、IaCはTypeScript（CDK）|
| クラウド | AWSを想定。ただし実デプロイは行わない |
| 認証 | PoCのため未実装。シングルユーザー前提 |
| デプロイ | IaC（AWS CDK）の作成までをスコープとする |
| OS | 開発はLinux/WSL2/macOSを想定 |
