# クラウドAIへのハンドオフ

## いつ委譲を検討するか

以下のいずれかに当てはまる作業は、Cloud Agent / GitHub Actions への委譲を検討する。

- 想定30分以上の **独立性の高い** 実装・リファクタ
- 大量のファイルにわたる機械的修正（型エラー一括修正、依存更新の追従等）
- 広範な調査（ライブラリ比較、性能計測、ベンチマーク）
- 並行で別観点を進めたいとき（worktree と組み合わせる）

逆に、以下は **ローカル** で進める。

- 設計判断を含む作業（人間 or 同じセッションで詰めるべき）
- スコープが流動的で、途中で方向転換しそうな作業
- 短時間で終わる修正（オーバーヘッドの方が大きい）

## ハンドオフパターン

| パターン | トリガ | 用途例 |
|----------|--------|--------|
| ローカル → Cloud Agent | ユーザー操作 | 長時間の実装、調査 |
| Issue → GitHub Actions 経由のAI | Issue ラベル付与 | 雑用タスク、依存更新 |
| PR → AIレビュー | PR 作成 | `/ultrareview` 相当の自動レビュー |

## ハンドオフ時に必ず渡す情報

委譲時には **コンテキスト不足のまま走らせない**。以下を明示する。

```markdown
## 関連
- Issue: #<num>
- PR: <なければ N/A>
- 既存資料: docs/requirements.md, docs/design.md

## ゴール
<完了条件を1-3行で。「動けばよい」ではなく具体的に>

## 触ってよいファイル / 触らないファイル
- 触ってよい: python/mar-api/ 以下
- 触らない: typescript/, docs/

## 期待する成果物
- PR 形式 / 報告書形式 のどちらか
- 含めるべき内容（実装変更、テスト、ドキュメント更新の有無）

## 制約
- 〆切（あれば）
- 使ってよいツール / 使ってはいけないツール
- スコープから外れたら止まる
```

このブロックは `.claude/handoff-template.md`（未作成）からコピーする運用にする。

## ハンドオフ後の追跡

- 委譲先には **作業ログを残させる**（GitHub の PR コメント、または Issue コメント）。
- 完了時、ローカル側で以下を確認:
  - スコープから外れていないか
  - テストが通っているか
  - 残課題が明示されているか
- 委譲した側（ローカル AI）は、戻ってきた成果物を **そのままマージしない**。必ず人間 or 別セッションが確認するフローを通す。

## やってはいけないこと

- コンテキスト不足のまま「いい感じにやって」と投げる
- 触ってよい範囲を曖昧にしたまま委譲する
- 委譲先の作業中に同じファイルをローカルでも触る（コンフリクトの温床）
- 委譲先が出した PR をローカル AI が **自分でレビューして自分でマージ** する（人間チェックを抜く）

## ハンドオフを試したら

`docs/journal/` にジャーナルを残す（`.claude/skills/review-flow/SKILL.md` のジャーナル節を参照）。どのパターンがうまく機能したかの蓄積が PoC 本来の成果物。
